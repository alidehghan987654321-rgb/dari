# سایت مادر گریفین (`gryffin.uk`)

صفحه‌ی اصلی شرکت: فهرست محصول‌های گریفین، که هر کدوم به سایت خودش می‌ره. صفحه کاملاً ایستاست: نه سرور داره، نه
دیتابیس، نه اسکریپت. فونت‌ها هم روی خود سایته، پس توی ایران هم سریع باز میشه.

## دو جور محصول

| جور | کجاست | کی |
|---|---|---|
| **سایت خودش** (`url`) | آدرس جدا، مثل `hunter.gryffin.uk` | هر محصولی که ورود، حساب کاربری، پرداخت یا سرور داره (شکارچی، Bookfin) |
| **زیر سایت مادر** (`"hosted": true`) | `gryffin.uk/SLUG/`، فایل‌هاش در `gryffin/SLUG/` | فقط صفحه‌های ایستا: معرفی، قیمت‌ها، راهنما |

چرا این جدایی؟ صفحه‌هایی که زیر `gryffin.uk` هستن یک «origin» رو با هم شریکن. اگه یکی‌شون حساب کاربری یا کوکی
داشت، بقیه بهش دسترسی پیدا می‌کردن. پس هر چیزی که حساب و پرداخت داره روی زیردامنه‌ی خودش می‌مونه.

## اضافه کردن یا عوض کردن یه محصول

همه‌ی محصول‌ها در `products.json` هستن. صفحه‌ی اصلی از روی همین فایل ساخته میشه؛ لیست توی `index.html` رو دستی
عوض نکن.

```json
{
  "slug": "bookfin",
  "name": "Bookfin",
  "tagline": "نوبت‌دهی آنلاین سالن",
  "for": "سالن‌های زیبایی و آرایشگاه‌ها",
  "what": "یک یا دو جمله درباره‌ی کاری که می‌کنه.",
  "letter": "B",
  "url": "https://bookfin.gryffin.uk/ir"
}
```

- `slug`: حروف کوچک انگلیسی، عدد و `-`. آدرس محصول‌های «زیر سایت مادر» هم از همین ساخته میشه.
- `logo`: یه عکس در `assets/img/`. اگه لوگو نداره، به جاش `letter` (یک یا دو حرف) بده.
- `url`: آدرس https سایت خود محصول. برای محصولی که زیر سایت مادره، به جاش `"hosted": true` بذار.
- توی متن‌ها خط تیره‌ی بلند (— یا –) نذار؛ از ویرگول و نقطه استفاده کن. سازنده جلوش رو می‌گیره.

بعد از هر تغییر:

```bash
python gryffin/build.py           # index.html و _headers رو از products.json می‌سازه
python gryffin/build.py --check   # فقط چک می‌کنه به‌روزن یا نه (دیپلوی هم همین رو چک می‌کنه)
```

### گذاشتن HTML یه محصول زیر سایت مادر

```bash
python gryffin/build.py add bookfin path/to/bookfin-site     # یه پوشه با index.html
python gryffin/build.py add bookfin path/to/page.html        # یا یه فایل HTML
```

فایل‌ها کپی میشن به `gryffin/bookfin/` و روی `gryffin.uk/bookfin/` در دسترسن. خود HTML عوض نمیشه. سازنده این‌ها
رو بهت می‌گه تا قبل از آنلاین شدن درستشون کنی:

- **آدرس‌هایی که با `/` شروع میشن** (مثل `/style.css`): زیر `/bookfin/` کار نمی‌کنن، باید نسبی بشن
  (`style.css`).
- **اسکریپت از سایت دیگه** (CDN): سیاست امنیتی (CSP) خود اون صفحه باید اجازه‌اش رو بده.
- **فیلد رمز، کوکی یا localStorage**: یعنی صفحه حساب کاربری داره و باید روی زیردامنه‌ی خودش بمونه.

بعد در `products.json` برای همون `slug` بنویس `"hosted": true` و `python gryffin/build.py` رو بزن.

### امنیت صفحه‌های محصول

صفحه‌ی اصلی سخت‌گیرانه‌ترین CSP رو داره (هیچ اسکریپتی اجرا نمیشه). صفحه‌های محصولی که زیر سایت مادرن همه‌ی
هدرهای امنیتی رو می‌گیرن، به جز همین CSP. چون HTML خودشون ممکنه اسکریپت داشته باشه، CSP خودشون رو با یه
`<meta http-equiv="Content-Security-Policy" content="...">` توی HTML خودشون تعیین می‌کنن. این‌طوری قانون‌های
صفحه‌ی اصلی اون‌ها رو خراب نمی‌کنه و قانون‌های اون‌ها هم صفحه‌ی اصلی رو شل نمی‌کنه. `_headers` رو `build.py`
می‌سازه؛ دستی عوضش نکن.

## طراحی

بازطراحی‌شده با قواعد Impeccable، Taste Skill و Emil Kowalski. فقط قواعد نوشته‌شده‌شون استفاده شده و برنامه‌هاشون
اجرا نشده.

- **رنگ:** زمینه‌ی لاجوردی بالای صفحه رو پر می‌کنه (اسم، جمله‌ی اصلی، فهرست محصول‌ها). زعفرانی تنها رنگ تأکیده:
  راه ورود به هر محصول، حلقه‌ی فوکوس و رنگ انتخاب متن. پایین صفحه زمینه‌ی سنگی روشن داره. حالت تاریک هم داره.
- **حروف:** عنوان‌ها با Lalezar (طراحی برنا ایزدپناه، بر اساس تابلوهای خیابان لاله‌زار)، متن با Vazirmatn. به
  حروف فارسی هیچ‌وقت فاصله‌ی بین حروف (letter-spacing) نده؛ اتصال حروف رو می‌شکنه.
- **شکل‌ها:** ردیف‌ها و کاشی‌ها گوشه‌ی ۱۶ پیکسلی دارن و چیزهای گرد کاملاً گردن.
- **حرکت:** فقط یک لحظه: موقع باز شدن، محصول‌ها پشت سر هم بالا میان. کسی که «کاهش حرکت» رو در دستگاهش روشن
  کرده، این حرکت رو نمی‌بینه.
- **اجتناب‌ها:** برچسب کوچک بالای عنوان، گرادیان، شیشه‌ی تزئینی، سایه‌ی بدون محو، فونت monospace برای تزئین،
  و ایموجی یا کاراکتر به جای آیکن (آیکن‌ها از Tabler هستن).

## آنلاین کردن

روی Cloudflare، به‌صورت یه Worker که فقط همین فایل‌ها رو سرو می‌کنه (`cloudflare/gryffin.jsonc`)، روی
`gryffin.uk` و `www.gryffin.uk`:

1. همون دو secret شکارچی باید در GitHub باشه: `CLOUDFLARE_API_TOKEN` و `CLOUDFLARE_ACCOUNT_ID`.
2. در GitHub برو به **Actions** ← **Deploy the Gryffin home page** ← **Run workflow**. قبل از دیپلوی چک میشه که
   صفحه با `products.json` یکی باشه.

این workflow عمداً **فقط دستی** اجرا میشه، نه با هر push، که دامنه‌ی اصلی اتفاقی عوض نشه. اگه `gryffin.uk` الان
به جای دیگه‌ای اشاره کنه، Cloudflare دیپلوی رو رد می‌کنه و چیزی رو عوض نمی‌کنه؛ اول اون رکورد DNS رو بردار.

برای امتحان روی کامپیوتر خودت: `python -m http.server -d gryffin 8000` و بعد `http://localhost:8000`.
