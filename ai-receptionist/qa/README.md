# تست خودکار مکالمه (M1)

سناریوهای `prompts/test_scenarios.md` را بعد از هر تغییر پرامپت یا پروفایل خودکار اجرا می‌کند تا کیفیت منشی اندازه‌گیری شود، نه حدس زده شود.
دروازه فاز ۱: **حداقل ۹۰٪ سناریوهای نوبت درست** و **صفر اطلاعات ساختگی**.

## اجرا

```bash
cd worker && npm install && cd ../qa && npm install     # یک بار
export ANTHROPIC_API_KEY=...                             # کلید خودتان؛ هرگز داخل گیت نگذارید
npm run qa                                               # همه سناریوها، حالت متنی
npm run qa -- --cases A1,B2,C3                           # چند سناریو
npm run qa -- --mutate no-invent-guard                   # پرامپت عمداً خراب: باید حداقل یک سناریو رد شود
npm run qa -- --llm-judge                                # بررسی ادب/کوتاهی/زبان با LLM (جدا گزارش می‌شود)
```

خروجی: `qa/report.md` و `qa/report.json` (در گیت نمی‌روند). کد خروج ۰ یعنی همه سناریوها قبول شدند.

در GitHub: **Actions ← Receptionist QA ← Run workflow** (secret مخزن: `ANTHROPIC_API_KEY`). گزارش در خلاصه اجرا و به‌صورت artifact می‌آید.

## چطور کار می‌کند

1. Worker با `wrangler dev` و یک D1 محلی تازه بالا می‌آید (بدون حساب Cloudflare). تلگرام و پیامک به یک mock محلی می‌روند.
2. برای هر سناریو یک کسب‌وکار جدا (`qa-a1`، `qa-b2`، ...) از روی `business_profile.example.json` ساخته می‌شود و نوبت‌های پیش‌فرض سناریو (fixtures) ثبت می‌شوند.
3. پرامپت سیستم با همان `scripts/prompt.mjs` ساخته می‌شود. زمان تماس شبیه‌سازی‌شده همیشه **چهارشنبه بعدی ساعت ۱۰:۳۰** به وقت کسب‌وکار است، پس «فردا» همیشه پنجشنبه است و نتیجه‌ها تکرارپذیرند.
4. مدل همان شش ابزار `config/tools.json` به‌علاوه ابزارهای سیستمی (`end_call`، `transfer_to_number`، `language_detection`، `skip_turn`) را می‌بیند. ابزارهای وب‌هوک واقعاً Worker محلی را صدا می‌زنند.
5. داور (`lib/judge.mjs`) بدون LLM بررسی می‌کند: ترتیب و آرگومان ابزارها، عبارت‌های لازم/ممنوع، زبان هر جواب، وضعیت نهایی در دیتابیس (نوبت ساخته/لغو/جابه‌جا شد؟ پیام گرفته شد؟ انتقال؟). **هر قیمتی که در پروفایل نیست** (عدد، £، یا به حروف فارسی/انگلیسی) اطلاعات ساختگی حساب می‌شود.

## تنظیمات (متغیر محیطی)

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `QA_PROVIDER` | `anthropic` | یا `openai` (هر API سازگار با OpenAI؛ `OPENAI_BASE_URL`) |
| `QA_MODEL` | مقدار `llm` در `config/agent_template.json` (الان `claude-sonnet-5`) / `gpt-4.1` | همان LLMی که ایجنت ElevenLabs استفاده می‌کند |
| `QA_EFFORT` | `low` | فقط Anthropic؛ برای جواب‌های کوتاه تلفنی |

## حالت پلتفرم (اختیاری، آزمایشی)

`npm run qa -- --platform` سناریوها را با API شبیه‌سازی مکالمه ElevenLabs روی **ایجنت واقعی** اجرا می‌کند (`QA_AGENT_ID`، `ELEVENLABS_API_KEY`).
ایجنت واقعی Worker واقعی را صدا می‌زند، پس فقط روی یک ایجنت و کسب‌وکار **تستی** اجرا کنید. سناریوهای نیازمند fixture، ساعت ثابت یا خرابی Worker در این حالت رد می‌شوند.
قالب درخواست از SDK رسمی elevenlabs-js برداشته شده؛ قبل از استفاده با مستندات فعلی چک کنید.

## اضافه کردن سناریو

یک مورد به `scenarios.yaml` اضافه کنید (توضیح فیلدها بالای همان فایل است) و `npm test` را بزنید تا ساختارش چک شود.
C4 (لهجه) و C13 (سکوت) صوتی‌اند و همچنان دستی با جدول `test_scenarios.md` تست می‌شوند.

## تست‌های خود ابزار

`npm test`: تست واحد داور و ساعت، و یک تست سرتاسری که runner، Worker و داور را با یک ایجنت اسکریپتی (بدون LLM) اجرا می‌کند.
